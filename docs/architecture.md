# Arquitectura\n\n## v0.3 — Validación\nLa v0.3 prepara los eventos y reglas necesarios para distinguir visualizaciones válidas de tráfico artificial.\n\n## v0.4 — Backend privado + Web pública\nLa separación propuesta es:\n\n```text\n                    ┌──────────────────────────┐\n                    │ GitHub público           │\n                    │ DeepAds Web              │\n                    │ + Vercel Frontend        │\n                    └────────────┬─────────────┘\n                                 │ HTTPS\n                                 ▼\n                    ┌──────────────────────────┐\n                    │ Backend privado           │\n                    │ DeepAds API              │\n                    ├──────────────────────────┤\n                    │ Campañas                 │\n                    │ Embeds                   │\n                    │ Eventos                  │\n                    │ Validación               │\n                    │ Anti-abuso               │\n                    │ Porcentaje de exposición │\n                    └────────────┬─────────────┘\n                                 │\n                                 ▼\n                         Base de datos\n```\n\n### Porcentaje de exposición\nEl backend será la fuente de verdad para el porcentaje calculado de cada campaña. La API puede devolver, por ejemplo:\n\n```json\n{\n  "campaignId": "camp_example",\n  "validViews": 25,\n  "exposurePercent": 0.5\n}\n```\n\nEse porcentaje es un dato para que servicios propios como un motor de búsqueda o una tienda de aplicaciones puedan aplicar sus propias reglas de recomendación.\n\n**Importante:** el porcentaje no debería significar automáticamente que un anuncio ocupa una posición determinada. La integración decide cómo usarlo y debe mantener reglas transparentes.\n\n## Prototipo\nLa versión inicial puede funcionar como una aplicación web estática:\n\n```text\nGitHub Pages\n    │\n    ├── Landing\n    ├── Documentación\n    └── Demo\n```\n\n## Seguridad\nLos secretos de servidor deben permanecer exclusivamente en el backend y en variables de entorno del proveedor de despliegue.\n\nEl frontend nunca debe recibir claves administrativas.\n\nLos embeds reales deben utilizar permisos mínimos y ser revocables.\n\n## Integraciones\nUn motor de búsqueda, una tienda de aplicaciones o un sitio web puede consumir la API y decidir cómo incorporar el porcentaje de exposición dentro de sus propias reglas.\n\nLa integración no debe convertir DeepAds en un mecanismo automático de posicionamiento absoluto.\n\n## Repositorios\n- **Público:** `anyelo888ra-ux/deepads-opensource` — frontend/web, documentación y demos.\n- **Privado:** repositorio separado para el backend de DeepAds. Su nombre se decidirá al crearlo.\n
